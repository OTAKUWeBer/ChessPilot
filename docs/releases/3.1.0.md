# ChessPilot 3.1.0 — More Android devices, clearer setup

ChessPilot 3.1.0 expands Android downloads to 32-bit ARM, ARM64 and x86-64, adds a universal APK, and improves the instructions for Android installation and touch-control permissions. Windows and Linux packages are rebuilt from the same release source.

## What's new

- **Four Android packages:** choose a smaller APK matching your Android system, or the universal APK containing all three supported architectures. Each includes the matching Rust runtime, ONNX Runtime and Stockfish engine. ARMv7 uses 32-bit Stockfish; ARM64 includes baseline and CPU-supported dot-product engines; x86-64 uses a baseline SSE2 engine.
- **Clearer phone setup:** touch control explains what Accessibility is used for before opening system settings. Restricted-settings help includes the main Settings → Apps route when an App info shortcut hides the required menu. Help and Exit stay visible while scrolling the dashboard.
- **Installation troubleshooting:** separate instructions cover Play Protect installation blocks and Android's restricted touch-control setting. Completing one does not automatically resolve the other.
- **32-bit compatibility fix:** the Android frame-buffer size check now works on 32-bit ARM and rejects sizes beyond Rust's valid slice limit.
- **Updated desktop builds:** Windows setup/portable and Linux portable/AppImage/DEB/installer packages include the current source, bundled detector model and dependency notices. Desktop gameplay and Wayland backends retain their existing behavior.

Capture, ONNX detection and Stockfish analysis run locally. Desktop checks for a compatible engine and downloads it when missing; Android includes its engines and network. Stockfish is CPU-based; this release does not enable GPU acceleration.

Android requires Android 7/API 24 or newer. There is no 32-bit x86 Flutter release build. Universal covers the listed architectures, not every device or Android version. Build tools, Flutter, Rust and Python are not required to run the downloaded app.

## Android installation and first launch

Install the matching APK, enable **ChessPilot touch control**, then approve sharing the **entire display**. Allow notifications for visible running controls. Move the overlay away from the board, choose your color, and use Play or Auto. **Stop** pauses moves; **Exit** also ends screen sharing and closes the engine.

If touch control is greyed out, open **Settings → Apps → App management / See all apps → ChessPilot → ⋮ → Allow restricted settings**. Complete the phone's confirmation, then return to Accessibility and enable ChessPilot touch control. Menu names vary. Full [installation and permission instructions](https://github.com/OTAKUWeBer/ChessPilot/blob/main/docs/INSTALLING.md#android-installation-and-restricted-settings) include the missing-menu case and Play Protect troubleshooting.

**Play Protect:** normal APK installation may still be blocked because the app uses Accessibility gestures. This release does not claim Google approval. The appeal submitted for an earlier 3.0.1 APK does not establish approval of these different 3.1.0 files. If choosing to temporarily disable scanning, review the documented risks and turn it back on afterward; Google may still flag or disable the app. Accessibility consent remains a separate requirement.

## Updating and compatibility

- **Android:** build 5 is newer than 3.0.1 build 4. All four release APKs must retain the existing maintainer signing identity so they can update existing 3.0.x installs. Do not uninstall just to switch between compatible APK variants. The certificate is still a development certificate; publisher-signing configuration is now supported, but no silent key migration is claimed.
- **Windows:** close ChessPilot and run the new installer into the existing installation folder. For portable use, replace the complete application bundle while preserving your engine/options. The Windows installer remains unsigned.
- **Linux:** replace the one-file app/AppImage or install the newer DEB/`.run`. Persistent engine/settings locations are unchanged. Builds use Ubuntu 22.04 as a compatibility baseline; host architecture, glibc and graphics drivers still matter.

Linux automation supports X11/XTEST and wlroots Wayland sessions exposing screencopy and virtual-pointer protocols with `grim`. GNOME/KDE Wayland portal automation is not implemented. macOS and iOS are not supported. These builds do not certify every distro, compositor, phone or screen configuration; extended gameplay/performance and additional device coverage remain ongoing.

See the [build guide](https://github.com/OTAKUWeBer/ChessPilot/blob/main/docs/BUILDING.md), [engine configuration](https://github.com/OTAKUWeBer/ChessPilot/blob/main/docs/ENGINE_CONFIG.md), and [test evidence](https://github.com/OTAKUWeBer/ChessPilot/blob/main/docs/TESTING.md).
