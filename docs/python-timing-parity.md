# Python timing ledger

Python source paths in this historical reference refer to the [main branch](https://github.com/OTAKUWeBer/ChessPilot/tree/main). This standalone branch keeps frozen comparison data, not the Python application.


This inventories every `sleep` and `QTimer.singleShot` call in the unchanged Python source. Each row identifies its native destination or an explicit control-flow change. A recorded replacement is not a claim that the Python schedule is copied literally. In particular, no uncertain move is sent twice merely to keep an old retry loop.

Gameplay waits execute off Flutter’s UI thread and are cancellation-aware. Android gestures use callbacks and currently use 50 ms taps / 200 ms drags, with 40 ms between completed click-mode taps; Drag/Click have passed on one Android 14 phone; broader device and special-move calibration remains pending. X11 additionally preserves PyAutoGUI’s implicit 100 ms pause (drag 300 ms; click 240 ms); its 50 ms moveTo is below PyAutoGUI’s interpolation threshold.

The data behind this table is in [timing-inventory.json](timing-inventory.json). Source hashes allow later parity work to detect stale entries. Windows/X11 pointer return now follows the complete verified manual transaction, under native input ownership. Windows movement is immediate; X11 preserves the 100 ms PyAutoGUI pause. Inspection of the installed Python implementation confirms that `moveTo(duration=0.1)` is at its interpolation threshold and therefore moves immediately before that pause, rather than taking 200 ms. Wayland omits Python's click-to-return helper: it must not click Play, and GTK has no reliable global app-window position there. Move and promotion offsets are ported through the shared controller, with an additional interior bound for tiny targets. GPU/NPU acceleration is additional work after parity, and must pass result and end-to-end latency checks before automatic selection.

Windows reliability correction: sliced gesture waits now subtract the actual elapsed wait (including timer oversleep), preserving the requested 40/20/40 ms drag and 20 ms click holds without multiplying them on coarse Windows timers. An early manual Play with confirmed history waits for and reconciles one legal opponent reply before analysis. Detector jitter is bounded by 4% of a square, capped at 6 px, at all board corners; the recorded 3 px jitter no longer ends Auto. Rejected position/history baselines are discarded so a later explicit Play can resynchronize rather than repeat the same error. Capture bounds, fresh pre-input observations, Stop and one-dispatch verification remain enforced.
